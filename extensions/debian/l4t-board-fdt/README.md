# l4t-board-fdt

Выбирает дерево устройств под конкретную плату Jetson — вписывает строку
`FDT` в запись `kvm` файла `extlinux.conf`. Ядро с KVM и все пропатченные
деревья кладёт в базовый образ [`l4t-kernel-kvm`](../l4t-kernel-kvm/README.md);
этот слой выбирает одно из них за секунды.

> **Живая машина — с `--accept-risk`.** Меняет дерево устройств, с которым грузится ядро kvm (строка FDT в /boot/extlinux/extlinux.conf); применится после перезагрузки. Неверное дерево модуля даёт плату, которая не находит корень, а плата без монитора чинится только последовательной консолью или прошивкой QSPI
<!-- /catalog:facts -->

## Что делает

- **`install`** — единственный хук. Проверяет плату и образ (см. «Отказы»),
  снимает копию `extlinux.conf` до первой правки cream
  (`extlinux.conf.cream-orig`, **один раз**, больше не перезаписывается) и
  вписывает строку `FDT /boot/<L4T_BOARD>-kvm.dtb` в запись `LABEL kvm`.
  Правку делает разбор на `python3`, а не `sed`: идемпотентность требует разбора
  записи `kvm` целиком. Файл пишется через временный и `rename` — с прежним
  режимом и владельцем.
- **`configure`** — нет: строка `FDT` — часть образа, а не настройка устройства.
- **`remove`** — нет: вернуть вендорское дерево — ручная работа (см. «Откат»).

| Код `install` | Когда |
|---|---|
| 10 | строка `FDT` записана — применится после перезагрузки |
| 0 | эта плата уже выбрана, файл не менялся |
| 20 | нет `/boot/extlinux/extlinux.conf` — не L4T-образ |
| 1 | отказ (см. «Отказы») |

## Параметры

<!-- catalog:params -->
| Ключ | Тип | Умолчание | Что задаёт |
|---|---|---|---|
| `L4T_BOARD` | строка `^[a-z0-9][a-z0-9._-]{0,127}$` | пусто | имя дерева устройств платы без суффикса -kvm (tegra210-p3448-0000-p3449-0000-a02); обязателен *(только при установке)* |
<!-- /catalog:params -->

`L4T_BOARD` обязателен: без него отказ. Из значения собирается путь
`/boot/<значение>-kvm.dtb`; суффикс `-kvm` добавляет расширение, а не автор
VMFILE: в VMFILE стоит имя **платы**, и знать про внутреннюю раскладку `/boot`
ему незачем. Хвост `.dtb` в значении допустим — он срезается, так что `…-a02` и
`…-a02.dtb` дают один и тот же путь. Только `[a-z0-9._-]`, без пути.

Ключ — параметр установки: сменить плату — `cream install l4t-board-fdt
L4T_BOARD=<другая>` (хук перезапускается, `cream set` такой ключ не меняет).
Как узнать имя своей платы — «Как узнать имя своей платы».

## Установка

В образе bisquite (VMFILE) — основное назначение:

```dockerfile
RUN_COMMAND cream install --with-deps l4t-board-fdt L4T_BOARD=tegra210-p3448-0000-p3449-0000-a02
```

Слой выполняет код внутри гостя (`build: exec`), поэтому собирать надо на
**arm64-хосте**: libguestfs не выполняет код гостя чужой архитектуры.

На живой плате ([как подключить каталог](../../../docs/getting-started.md)) —
только с `--accept-risk` (меняется дерево, с которым грузится плата):

```bash
sudo cream install --with-deps --accept-risk l4t-board-fdt L4T_BOARD=tegra210-p3448-0000-p3449-0000-a02
sudo reboot
```

| Когда | Что происходит |

| загрузка | ничего: `configure` нет, дерево применяется загрузчиком |

## Известные ограничения

**Назначение — сборка.** Строка `FDT` — часть образа, а не настройка
устройства, поэтому `configure` (запуск на каждой загрузке) у слоя нет:
выбранная на загрузке, она давала бы платам разные `extlinux.conf` при одном
теге образа. Живая установка (`live: confirm`) — для одной платы на столе,
с `--accept-risk` и перезагрузкой.

**Только Tegra210 по факту.** `arch: [arm64]` формально допускает любой
Jetson, но деревья с суффиксом `-kvm` кладёт `l4t-kernel-kvm`, а он
t210-only и проверяет это явно, отказывая в первую минуту
(см. [его «Известные ограничения»](../l4t-kernel-kvm/README.md)). То есть сегодня
вся пара расширений — про Nano и TX1. Сам этот слой семейство SoC **не проверяет
и проверять не должен**: он сверяет существование конкретного файла, и маска в
отказе — по суффиксу `-kvm`, а не по семейству. Появятся `-kvm.dtb` другого
семейства — слой выберет их без правок.

**Соответствие дерева реальной плате не проверяется.** Расширение проверяет,
что файл существует, и ничего не знает о том, на какую плату поедет образ:
`L4T_BOARD` — утверждение оператора. Перепутанная **несущая** даст рабочую
плату с неправильными камерами, перепутанный **модуль** — плату, которая
не находит корень (см. «Чем различаются деревья»).

**Место.** Хранилище контент-адресуемое, а слой меняет `extlinux.conf` —
содержимое диска другое, дедуп не срабатывает, и **каждый вариант это
полная копия образа**. Долгоживущий артефакт — база; вариант собирают
перед прошивкой и удаляют после.

**Хука `remove` нет** — см. «Откат».

## Подробности

### Зачем

Ядро L4T с KVM собирается **2 часа 15 минут** ([`l4t-kernel-kvm`](../l4t-kernel-kvm/README.md)).
Если бы сборка ядра вписывала ровно одну строку `FDT`, образ был бы привязан к
одной паре «модуль + несущая плата». Пар таких семь — то есть семь двухчасовых
сборок ради строки в текстовом файле.

**Ядро от платы не зависит вовсе.** Зависит только дерево. Поэтому
`l4t-kernel-kvm` кладёт в `/boot` все пропатченные деревья (замер
2026-09-04: 22 штуки, все платы Tegra210) и не пишет `FDT`, а выбор
делает этот слой — за секунды, поверх готовой базы.

```
jetson-nano-kvm:32.6.1        ядро + все деревья, без FDT     2 ч 15 мин на Nano
      ↓ FROM + пакеты, стек CV/ML, рабочий стол
jetson-nano-robot:32.6.1      минуты
      ↓ FROM + cream install l4t-board-fdt
jetson-nano-robot:32.6.1-a02   /   jetson-nano-robot:32.6.1-b01   СЕКУНДЫ
```

### Как узнать имя своей платы

На целевом устройстве:

```console
$ cat /proc/device-tree/compatible
nvidia,p3449-0000-a02+p3448-0000-a02 nvidia,jetson-nano nvidia,tegra210
```

Читается как «несущая `p3449-0000-a02`, модуль `p3448-0000-a02`», а имя
дерева собирается в обратном порядке — модуль, потом несущая:

```
L4T_BOARD=tegra210-p3448-0000-p3449-0000-a02
```

Список того, что есть в конкретном образе, печатает сам отказ расширения.
Строится он по маске `*-kvm.dtb` в `/boot` — по **суффиксу**, который ставит
`l4t-kernel-kvm`, а не по семейству SoC: суффикс наш и известен, семейство —
нет. Маска по семейству (`tegra210-*-kvm.dtb`) на образе другой Tegra давала бы
пустой список при лежащих рядом деревьях и ложную подсказку «базовый образ
собран без l4t-kernel-kvm».

На вопрос «собран ли базовый образ с `l4t-kernel-kvm`» отвечает
проверка, которая его и проверяет: запись `LABEL kvm` в `extlinux.conf`.
Она стоит **раньше** поиска дерева, поэтому подсказка про отсутствующий
`l4t-kernel-kvm` печатается только тогда, когда это установленный факт.

### Какие платы бывают

| Имя | Модуль | Несущая | Приметы |
|---|---|---|---|
| `tegra210-p3448-0000-p3449-0000-a02` | microSD | A02 | девкит, **один** разъём камеры |
| `tegra210-p3448-0000-p3449-0000-b00` | microSD | B01 | девкит, **два** разъёма камеры |
| `tegra210-p3448-0002-p3449-0000-a02` | eMMC | A02 | production-модуль |
| `tegra210-p3448-0002-p3449-0000-b00` | eMMC | B01 | production-модуль |
| `tegra210-p3448-0003-p3542-0000` | 2 ГБ | p3542 | другая несущая целиком |

Плюс варианты `-a00`, `-a01` (ранние несущие) и `-hdmi-dsi`. Последние
собираются, но чем отличаются — не замерено, и обещать их нечего.

### Чем различаются деревья, и почему это важно

Замер 2026-09-04, `dtc -I dtb -O dts` плюс `diff`:

| Пара | Различий | Что различается | Ломает загрузку? |
|---|---|---|---|
| `a02` ↔ `b00` (несущая) | 2226 строк | только камеры: `cam_i2cmux`, `channel@0/1`, `i2c@0/1`, `endpoint@0..3` | **нет** |
| `p3448-0000` ↔ `-0002` (модуль) | 524 строки | среди прочего пинмукс `sdmmc1` — контроллер **microSD**, есть только у `-0000` | **да** |

Практический вывод: перепутанная **несущая** даёт работающую плату
с неправильными камерами, перепутанный **модуль** — плату, которая
не находит корень.

Второе не гипотеза: запасная ветка `l4t-kernel-kvm` однажды выбрала
`p3448-0002` для девкита с microSD, и образ пришлось пересобирать.
Отсюда отказ ниже вместо «возьмём что-нибудь».

### Отказы

Порядок проверок несущий, поэтому и список идёт в том порядке, в каком
они стоят:

- **`L4T_BOARD` не задан** — сообщение объясняет, как узнать своё имя;
- **нет `/boot/extlinux/extlinux.conf`** — это вообще не L4T-образ (код 20,
  «неприменимо»); `extlinux.conf` — символическая ссылка — отказ: через ссылку
  расширение не пишет;
- **нет `LABEL kvm` в `extlinux.conf`** — база собрана без `l4t-kernel-kvm`,
  выбирать нечего. Это **единственное** место, где расширение говорит про
  отсутствие `l4t-kernel-kvm`, и говорит оно по факту, а не по маске имён;
- **дерева нет в образе** — печатается список того, что есть (маска
  `*-kvm.dtb`, см. выше). Пустой список здесь означает другое: запись
  `LABEL kvm` есть, то есть ядро в образе стоит, а деревья из `/boot`
  удалены или переименованы;
- **строку не удалось записать** — разбор записи `kvm` не нашёл, куда её
  поставить; сам `extlinux.conf` остаётся нетронутым, копия не снимается. Случай
  недостижим, пока стоит проверка `LABEL kvm` выше: разбор ищет ровно ту
  запись, наличие которой она подтвердила.

Все — отказ, а не предупреждение. Молча вписанный путь к
несуществующему дереву даёт незагружаемую плату, а плата без монитора
не чинится вовсе: только последовательной консолью или перепрошивкой QSPI.

### Что править и чем перезапускать

Параметр времени выполнения здесь один, и он не переменная, а строка
в файле: `FDT` внутри записи `LABEL kvm` файла `/boot/extlinux/extlinux.conf`.
Службы нет и перезапускать нечего — применяется это **перезагрузкой**.

| Что менять | Где лежит на устройстве | Чем применить |
|---|---|---|
| выбранное дерево | строка `FDT` в записи `LABEL kvm`, `/boot/extlinux/extlinux.conf` | `reboot` |
| какая запись грузится по умолчанию | строка `DEFAULT` там же | `reboot` |
| откат | `/boot/extlinux/extlinux.conf.cream-orig` — файл до **первой** правки cream (этим слоем или `l4t-kernel-kvm`) | вернуть на место и `reboot` |

Что есть в образе, смотрят так:

```console
$ ls /boot/*-kvm.dtb
```

Ошиблись деревом и плата не грузится — помогает только последовательная
консоль или перепрошивка QSPI, поэтому правьте файл до записи носителя,
а не после.

### Идемпотентность

Слой можно применять поверх образа, где `FDT` уже стоит: прежняя строка
заменяется, лишние (если файл был порчен и их несколько) отбрасываются;
та же плата второй раз — код 0 и ни одного изменённого байта. Файл пишется
через временный и `rename` — с прежним режимом и владельцем.

### Откат

Копия `extlinux.conf.cream-orig` снимается **один раз**, перед первой правкой,
и больше не перезаписывается — ни повтором, ни сменой платы, ни
`l4t-kernel-kvm` (он ведёт ту же копию): в ней всегда файл до cream.

Хука `remove` нет: вернуть вендорское дерево на плате без монитора — ручная
работа (строка `FDT` или `extlinux.conf.cream-orig` и `reboot`), запись
реестра снимает `cream remove --forget l4t-board-fdt`.

### Как проверить вариант

```console
$ virt-cat -a вариант.qcow2 /boot/extlinux/extlinux.conf | grep -A5 'LABEL kvm'
```

На устройстве после загрузки:

```console
$ uname -r                        # …-tegra-kvm
$ ls -l /dev/kvm
$ dmesg | grep -i gicv            # строки про trapping быть НЕ должно
```

## Проверки

- **V** — `make cream-validate`, `tools/lint-hooks.sh`, `make check-names`.
- **H** — `tests/test-hooks.sh`: манифест; `install` на подменённом корне —
  отказы (нет `L4T_BOARD`, нет `LABEL kvm`, нет дерева — со списком, ссылка
  вместо `extlinux.conf`) без правки файла и без копии; копия
  `extlinux.conf.cream-orig` — исходный файл и после повтора, и после смены
  платы; повтор — файл байт в байт тот же; запись `kvm` не последней.
- **L** — нет: живая плата Jetson в CI недоступна.
