# pixelflux-v4l2m2m

Формат cream/v1 (план 2026-10-19, Task 27), версия 2.0.0.

Аппаратное кодирование H.264 в Selkies на платах, чей кодер выставлен
стандартным **V4L2 M2M**: Raspberry Pi 3/4 и CM4 (`bcm2835-codec`), а тем же
интерфейсом — RK356x и i.MX8M.

С **Selkies 2.0.0** кодирование даёт сам базовый образ: релиз несёт
`pixelflux 2.1.0` с бэкендом `v4l2m2m`, и лестница кодеров сама падает с
VA-API (которого на Малине нет) на M2M. Подменять и патчить больше нечего —
расширение свелось к **проверке**.

## Что даёт

Замер на Raspberry Pi 4, живой рабочий стол 1080p, одна сессия, разница только
в `use_cpu`:

| | кадров | процессор |
|---|---|---|
| Железо (`v4l2m2m`) | 10.1 fps | **0.378 ядра** |
| Софт (x264) | 12.2 fps | **1.128 ядра** |

Втрое меньше процессора. Частота при этом у софта чуть выше: x264 раскладывается
на четыре ядра, а аппаратный движок кодирует по кадру за раз. Расширение продаёт
ядра, не частоту.

## Манифест

| поле | значение |
|---|---|
| `version`, `cream` | `2.0.0`, `">=1.1.0"` (стадия `graphical`) |
| `platform.arch` | `[arm64]` — M2M-платы парка |
| `targets` | `build: exec`, `live: yes` |
| `provides` / `requires` | `hardware-video-encoding` / `web-remote-desktop` |
| `conflicts.extensions` | `[pixelflux-tegra]` |
| хуки | `install`, `configure` (стадия `graphical`), `remove` |

Ставится после `selkies` (`requires`; `install` отказывает без `/opt/selkies/current`).

## Что проверяется

**`install`** — что базовый `pixelflux` несёт бэкенд `v4l2m2m` (апстрим уронит —
установка встанет, а не уедет тихо в софт). На **живой машине** (`CREAM_PHASE=live`)
ещё и проба: pixelflux не называет `v4l2m2m` для H.264 — код **20**, «здесь
неприменимо» (рулинг Р11). На сборке устройств в appliance нет — пробы нет.
Пишет только отпечаток `/var/lib/cream/ext/pixelflux-v4l2m2m/stamp`
(`prefix=/opt/selkies/<версия>`, временный файл и `rename`); в дерево `selkies` — ничего.

**`configure`** (каждая загрузка, стадия `graphical`; было `verify-pixelflux-v4l2m2m.service`)
— спрашивает у pixelflux, объявлен ли `v4l2m2m` для h264. Нет — **предупреждение
в журнале и код 0** (Р11) с перечнем узлов `/dev/video*`: «узлов нет» и «узлы есть,
но не подошли» чинятся по-разному. Устаревший отпечаток (AppImage подняли без
переустановки) — тоже предупреждение. Журнал сессии для этого не годится: строка
`Encoder: …` появляется только при подключённом клиенте.

**`remove`** — снимает отпечаток.

## Проверки

- **V** — `make cream-validate`; **H** — `tests/test-pixelflux-v4l2m2m.sh` (манифест,
  `install` live/build, 20, отказы, отпечаток не по ссылке и без перезаписи;
  `configure` по Р11; `remove`).
- **P** — ожидает: Raspberry Pi 4 с `selkies`.

## Чего расширение не делает

**Не ставит и не подменяет колесо.** Бэкенд уже в базовом Selkies; роль
расширения — проверка, а не установка.

**Не ставится на платы без кодера.** На Pi 5 его нет в кремнии вовсе — там
расширение в цепочке указывать не нужно: `install` на живой машине ответит 20, а на
загрузке будет предупреждение.

**Не подкладывает libxcb и не собирает шим gbm.** Это болезни L4T, которые
лечит `pixelflux-tegra`; на Малине AppImage работает со своими библиотеками.

## Когда исчезнет совсем

Если Selkies когда-нибудь сам начнёт громко отказывать при откате в софт на
плате, от которой ждут железа, расширение станет не нужно. Пока такой проверки
у него нет — её и делает это расширение.
