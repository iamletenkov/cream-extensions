# cuda-toolkit

Ставит CUDA Toolkit (`nvcc`, библиотеки, заголовки) на Jetson из
apt-репозитория `jetson/common`, который уже подключён базовым образом L4T —
собственного источника пакетов расширение не заводит (исключение — R32 с
закомментированным источником вендора, см. ниже). Кладёт системный профиль PATH.

## Что делает

- **`install`** — на L4T R36 ставит `cuda-toolkit` из `jetson/common` и пишет
  профиль `/etc/profile.d/cuda-toolkit.sh` (через временный файл и переименование —
  символическая ссылка на его месте заменяется, а не проходится). Нет
  `/etc/nv_tegra_release` (не Jetson) — код **20** до apt, а не отказ 1.
- **`install` на Jetson Nano** (L4T R32, JetPack 4.6, Ubuntu 18.04/20.04) — ставится
  `cuda-toolkit-10-2` (CUDA 10.2): способность `cuda` есть и у Nano (её требует
  `l4t-pytorch`). CUDA 10.2 уже в образе вендора (`/usr/local/cuda-10.2/bin/nvcc`,
  образ Q-engineering) — apt не зовётся, пишется только профиль (и ссылка
  `/usr/local/cuda`, если её нет). Нет CUDA и нет активной строки `jetson/common`
  (вендор её закомментировал) — расширение заводит свой источник
  `/etc/apt/sources.list.d/cream-cuda-toolkit.list` на ветку `r32.<ревизия>`
  (r32.4…r32.7) с `signed-by` ключом NVIDIA Jetson OTA из
  `files/jetson-ota-public.asc`; ключ до использования сверяется с пином sha256 в хуке.
- **`remove`** — свои пакеты, профиль, а на R32 — и свой источник, ключ и свою
  ссылку (см. «Что снимает `remove`»).

| Код `install` | Когда |
|---|---|
| 0 | поставлено (или уже стояло) |
| 1 | нет источника `jetson/common`, apt не прошёл, нет `/usr/local/cuda` после установки |
| 20 | нет `/etc/nv_tegra_release` — не Jetson, ставить неоткуда (до apt) |

## Установка

На живой плате Jetson:

```bash
sudo cream install --with-deps cuda-toolkit
sudo cream remove cuda-toolkit
```

В образе bisquite (VMFILE; основной путь):

```dockerfile
RUN_COMMAND cream install --with-deps cuda-toolkit
```

## Этапы

| Когда | Что происходит |
|---|---|
| сборка образа / `cream install` | пакеты CUDA (или только профиль, если CUDA уже в образе), профиль PATH |
| `cream remove` | свои пакеты, профиль; на R32 — свой источник, ключ, ссылка |

## Известные ограничения

- Не кандидат в базовый образ флота: образ вырастает на единицы гигабайт (см.
  «Размер и время») — только в прикладной слой тех VMFILE, кому CUDA действительно
  нужна.

## Подробности

### Зачем

CUDA-рантайм (`nvidia-l4t-cuda`) в образ L4T входит всегда — без него не
работают даже библиотеки самой Tegra. А вот компилятор и заголовки
(`nvcc`, `cuda-cudart-dev` и остальные ~200 подпакетов `cuda-toolkit`) —
нет: их ставит только этот шаг, отдельно и по требованию, потому что часть
флота (роботы без инференса) их не использует вовсе, а набор тяжёлый.

### Проверено

Живая плата, JetPack 6.2.1, L4T 36.4.3, 2026-09-12:

```
cuda-toolkit | 12.6.11-1 | https://repo.download.nvidia.com/jetson/common r36.4/main arm64 Packages
```

### Почему `cuda-toolkit`, а не `cuda`

Пакет `cuda` тянет `cuda-drivers` — на Jetson GPU-стек не отдельный
драйвер, а часть L4T (`nvidia-l4t-core`), и `cuda-drivers` в этом смысле
просто не существует. `cuda-toolkit` берёт компилятор и библиотеки без
этого хвоста.

### PATH и LD_LIBRARY_PATH

Deb-пакет NVIDIA, в отличие от runfile-инсталлятора, профиль сам не
прописывает (это задокументированное поведение в CUDA Installation Guide,
раздел post-install actions). Расширение кладёт
`/etc/profile.d/cuda-toolkit.sh` — системно, при сборке, потому что
пользователь появится только на первой загрузке через cloud-init, а CUDA
нужна любому, кто войдёт в систему, а не только тому, кто её ставил.

`/usr/local/cuda` — симлинк на `/usr/local/cuda-<версия>`, версия в профиле
не прибита: обновление пакета не оставит профиль указывающим в никуда.

### Размер и время

Install-size самого мета-пакета в apt показывает единицы килобайт — это
обманчиво, реальный вес в зависимостях. На арм64-Jetson через эмулируемую
или нативную сборку установка занимает несколько минут; конечный образ
вырастает на единицы гигабайт.

### Что снимает `remove`

`install` записывает в `/var/lib/cream/ext/cuda-toolkit/packages` только пакеты, которых
до него не было; повторный `install` (`--reinstall`) запись не меняет. `remove`
сначала спрашивает apt в режиме симуляции (`apt-get -s remove`): если вместе со
своими пакетами apt снял бы и чужие (от них зависит поставленное позже), хук
отказывает и ничего не меняет — снимите руками или `cream remove --forget cuda-toolkit`.
Иначе — `apt-get remove` своих пакетов и профиль `/etc/profile.d/cuda-toolkit.sh`;
на R32 — ещё свой источник, ключ и свою ссылку `/usr/local/cuda`. Пакеты, стоявшие
до cream, остаются.

## Проверки

- **V** — `make cream-validate`, `tools/check-names.sh`.
- **H** — `tests/test-cuda-toolkit.sh`: код 20 без L4T, отказ без источника,
  установка и повтор, профиль поверх символической ссылки, строка релиза как данные,
  пакет до cream, `remove` (свой, чужой, отказ при чужих зависимых).
- **P — ожидает.** Платы Jetson в CI нет: установка на живой плате (AGX Orin, R36)
  через `cream install` или сборка образа через bisquite проверяются вручную.
- **L** — не нужен: в контейнере нет `/etc/nv_tegra_release`, ответ — код 20, его
  проверяет H.
