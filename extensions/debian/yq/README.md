# yq

Ставит `yq` — статический бинарь [mikefarah/yq](https://github.com/mikefarah/yq)
в `/usr/local/bin/yq` по пину версии и sha256.

## Что делает

- **`install`** — качает `yq_linux_<arch>` выпуска `YQ_VERSION` через `curl`,
  до установки сверяет sha256 (пин `files/pin.env` или `YQ_SHA256`) и кладёт
  бинарь в `/usr/local/bin/yq`; версию и sha256 записывает в
  `/var/lib/cream/ext/yq/installed`.
  - **Свой бинарь** с нужной версией — повтор `install` ничего не делает.
    Другая версия — бинарь заменяется атомарно (скачать рядом → проверить → `mv`).
  - **Чужой mikefarah/yq** в `/usr/local/bin` или `/usr/bin` (поставлен не этим
    расширением) — не трогается, `install` выходит 0 без записи: перекрывать
    чужую установку ради номера версии значит трогать то, чего расширение не
    ставило. Нужен именно пин — снимите прежний бинарь до установки.
  - **kislyuk/yq из пакета** — остаётся на месте; свой бинарь ложится в
    `/usr/local/bin`, который в `PATH` раньше `/usr/bin`, с предупреждением.
    Пакет не удаляется: его зависимости не наши.
- **`remove`** — снимает `/usr/local/bin/yq`, только если это всё ещё бинарь
  из записи; изменённый оставляется с предупреждением. Чужой не трогается.

## Параметры

<!-- catalog:params -->
| Ключ | Тип | Умолчание | Что задаёт |
|---|---|---|---|
| `YQ_VERSION` | строка `^v[0-9]+\.[0-9]+\.[0-9]+$` | `v4.45.1` | выпуск mikefarah/yq; не пин каталога (files/pin.env) — только вместе с YQ_SHA256 *(только при установке)* |
| `YQ_SHA256` | строка `^[0-9a-f]{64}$` | пусто | sha256 yq_linux_<arch> машины для YQ_VERSION; пусто — из пина каталога *(только при установке)* |
<!-- /catalog:params -->

- `YQ_VERSION` — `scope: install`: смена переустанавливает бинарь.
- `YQ_SHA256` — пусто означает «из пина»; обязателен, если версия не пин.

Пин каталога — `files/pin.env`: версия и sha256 для `amd64` и `arm64`,
сверенные со столбцом SHA-256 файла `checksums` выпуска. Версия прибита
намеренно: `latest` означал бы, что та же сборка завтра даст другой образ.

## Установка

На машине с подключённым каталогом ([как подключить](../../../docs/getting-started.md)):

```bash
sudo cream install --with-deps yq                                   # пин каталога
sudo cream install --with-deps yq YQ_VERSION=v4.44.3 YQ_SHA256=…    # другой выпуск — только с его sha256
sudo cream remove yq
```

В образе bisquite (VMFILE) — до расширений, которым он нужен:

```dockerfile
RUN_COMMAND cream install --with-deps yq
```

## Этапы

| Когда | Что происходит |
|---|---|
| сборка образа / `cream install` | скачивание, сверка sha256, установка бинаря, запись `installed` |
| загрузка | ничего: хука `configure` нет |
| `cream set YQ_VERSION=…` | ключ `scope: install` — бинарь переустанавливается |
| `cream remove` | снимает свой бинарь, если он не изменён |

## Известные ограничения

- Чужой mikefarah/yq не заменяется: пока прежний бинарь не снят, пин не
  гарантирован.
- Пакетный kislyuk/yq остаётся в `/usr/bin` рядом со своим бинарём.

## Подробности

### Зачем отдельным расширением

**Имя `yq` носят два разных инструмента**, и языки запросов у них
несовместимы:

| | откуда | язык |
|---|---|---|
| kislyuk/yq | `apt install yq` в Debian/Ubuntu | jq |
| mikefarah/yq | бинарь с GitHub | свой |

Выражение `.x // empty` законно у первого и отвергается вторым —
`Error: invalid input text "empty"`.

Пока каждое расширение ставило `yq` само («пакет, если есть; бинарь,
если нет»), один и тот же образ давал **разный инструмент на разных
дистрибутивах**. Хуже того, расхождение проявлялось не на сборке,
а на первой загрузке устройства: замер 2026-09-06 на Jetson Nano —
три службы настройки упали с «не дождался пользователя cloud-init»,
хотя пользователь существовал с первых секунд.

Одно расширение — один инструмент, всегда один и тот же.

### Ubuntu 18.04 и 20.04

Статическому бинарю версия glibc не нужна, поэтому расширение принимает
Ubuntu от 18.04 (Debian — от 12): Jetson Nano (L4T R32) — это Ubuntu
18.04/20.04.

### Кто читает yq

Библиотека [`cloud-user`](../cloud-user/README.md) читает userdata
cloud-init этим `yq`; без него она идёт запасным путём (первая обычная
учётка), поэтому на образах с cloud-init `yq` ставится вместе с ней.
