# gdm-xorg

Переключает gdm3 на Xorg по согласию владельца: `WaylandEnable=false` в том файле,
который читает пакет gdm3, а `cream remove` возвращает прежнюю строку побайтно. Нужно
на машине со своим GNOME ([`existing-desktop`](../existing-desktop/README.md)), где
сеансы идут на Wayland, а [`selkies`](../selkies/README.md) и
[`x11vnc`](../x11vnc/README.md) видят только X-сервер.

## Что делает

- **`install`** — нет ни `/etc/gdm3/daemon.conf`, ни `/etc/gdm3/custom.conf` — код
  **20** («не GDM»). Строка уже `false` — код 0, файлы не трогаются, в записи помечено
  «было false». Иначе прежнее состояние строки — ключа нет, закомментирован или `true` —
  записывается в `$CREAM_STATE_DIR/wayland.before`, и только потом пишется
  `WaylandEnable=false`. На живой машине — код **10** (нужна перезагрузка): gdm **не
  перезапускается**, иначе оборвался бы сеанс владельца. При сборке образа — 0.
  Ссылка вместо файла (или вместо `/etc/gdm3`) — отказ, код 1, ничего не пишется.
- **`remove`** — строка возвращается побайтно, как её нашёл `install`: заменённая — на
  своё место, добавленная — убирается (вместе с добавленной группой `[daemon]`). Строки,
  которые за это время дописали другие, остаются. Строку, которую после установки
  поменяли руками, `remove` не трогает и предупреждает. Изменение на живой машине —
  код **10**.

Правят оба файла, какие есть: какой из них читает gdm3, решено при сборке пакета
(Debian — `daemon.conf`, Ubuntu — `custom.conf`), ключ в другом молча игнорируется.
Режим и владелец файла сохраняются. Код правки — общая библиотека
[`lib/gdm-wayland.sh`](../../../lib/gdm-wayland.sh), одна копия с
[`gnome`](../gnome/README.md).

## Установка

На машине с подключённым каталогом ([как подключить](../../../docs/getting-started.md)):

```bash
sudo cream install --with-deps --accept-risk gdm-xorg
cream show gdm-xorg
sudo reboot
```

`live: confirm` — без `--accept-risk` cream спросит согласие. После перезагрузки экран
входа и все сеансы GNOME — Xorg.

В образе bisquite (VMFILE):

```dockerfile
RUN_COMMAND cream install --with-deps gdm-xorg
```

## Этапы

| Когда | Что происходит |
|---|---|
| сборка образа / `cream install` | запись прежней строки, `WaylandEnable=false`; на живой машине — код 10, перезагрузка |
| загрузка | ничего: хука `configure` нет, gdm читает файл сам |
| `cream remove` | прежняя строка побайтно, запись снимается; на живой машине — код 10, перезагрузка |

## Известные ограничения

- С [`gnome`](../gnome/README.md) не ставится: строку `WaylandEnable` правят оба, а
  владелец у неё один (конфликт объявлен в манифесте).
- Только gdm3. LightDM и SDDM не трогает: у них Wayland — отдельный выбор сеанса.
- gdm не перезапускается ни при установке, ни при снятии: изменение действует после
  перезагрузки (или выхода из всех сеансов и ручного перезапуска gdm).
- Ссылку вместо файла конфигурации не правит: отказ без записи.
- Захвата Wayland в этом расширении нет (не-цель спеки
  [2026-11-12-existing-desktop](../../../docs/specs/2026-11-12-existing-desktop.md)).

## Проверки

- **V** — `make cream-validate`, `tools/lint-hooks.sh`, `make check-names`.
- **H** — `tests/test-gdm-xorg.sh`: четыре состояния строки в обоих файлах, нет gdm3 —
  20, ссылка — отказ без записи, побайтный возврат (`cmp`, режим), код 10 только на
  живой машине и только при изменении, `systemctl` не зовётся.
- **L** — `make test-live EXT=gdm-xorg` (`tests/live.env`): файлы пакета ложатся
  preseed'ом (`tests/live-root/`), `remove` возвращает их побайтно
  (`LIVE_EXPECT_RESTORED`); debian-12 и ubuntu-24.04.
