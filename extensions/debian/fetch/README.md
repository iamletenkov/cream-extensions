# fetch

Библиотека загрузки большого файла (AppImage, `.deb` релиза) по закреплённой
sha256 с повторами на обрыв соединения. Хуков нет: cream раскладывает `fetch.sh`
в `/opt/cream/ext/fetch/` и держит его, пока от библиотеки зависит хотя бы одно
расширение (спека cream §4.5).

## Что делает

Даёт потребителям функцию из `${CREAM_ROOT:-}/opt/cream/ext/fetch/fetch.sh`:

| Функция | Что делает |
|---|---|
| `fetch_verified ПУТЬ SHA256 АДРЕС…` | Адреса по очереди, на каждый — `FETCH_ATTEMPTS` попыток (умолчание 5) с паузой `FETCH_DELAY` с (умолчание 10). Файл пишется в `ПУТЬ.part` и становится `ПУТЬ` только при совпавшей sha256 |

- Коды: 0 — `ПУТЬ` — закреплённый файл; 1 — ни один адрес не отдал файл;
  2 — файл пришёл, но sha256 не та (без повторов: неверно содержимое, а не сеть);
  3 — неверный вызов (сумма не 64 hex, нет адреса, `FETCH_ATTEMPTS` не число ≥ 1).
- `ПУТЬ.part` не остаётся ни при каком исходе.
- Попыткой считается любой отказ curl, в том числе зависание: ниже 10 КБ/с
  60 с подряд. Ходит только по https и http.
- Сообщения — через `log_warn`/`log_error` вызывающего, если они определены;
  иначе stderr.

## Установка

Обычно библиотеку ставит cream по `depends` потребителя. Вручную, на машине с
подключённым каталогом ([как подключить](../../../docs/getting-started.md)):

```bash
sudo cream install fetch
cream show fetch
```

### Как подключить к своему расширению

Манифест потребителя:

```yaml
depends:
  - {name: fetch, version: ">=1.0.0 <2"}
```

Хук (curl потребитель ставит сам — у библиотеки нет `platform.commands`):

```bash
FETCH_LIB="$R/opt/cream/ext/fetch/fetch.sh"
[[ -f "$FETCH_LIB" ]] || { log_error "нет библиотеки fetch ($FETCH_LIB) — cream ставит её по depends"; exit 1; }
# shellcheck source=../../fetch/fetch.sh
source "$FETCH_LIB"
rc=0
fetch_verified "$WORK/asset" "$SHA256" "$URL" "$MIRROR_URL" || rc=$?
case "$rc" in
    0) ;;
    2) log_error "sha256 не совпала — не ставлю"; exit 1 ;;
    *) log_error "файл не скачался"; exit 1 ;;
esac
```

## Известные ограничения

- Докачки (`-C -`) нет: оборванная попытка начинается заново. Сервер без
  поддержки диапазонов дал бы на докачке отказ, а сумма проверяется всё равно.
- Мелкие загрузки (ключи apt, `.sha256`) каталог через библиотеку не ведёт: им
  хватает `--retry` curl.

## Подробности

### Зачем

curl 7.68 (Ubuntu 20.04 focal — корневая ФС L4T Jetson Nano) не повторяет
«Connection reset by peer» (curl 56) даже с `--retry 5`, а `--retry-all-errors`
появился только в 7.71. На приёмке на Jetson Nano (2026-10-22) установка
`selkies` падала на первом же обрыве. Поэтому попытки — свой цикл вокруг curl
на любую его ошибку; собственный `--retry` curl не используется — он умножил бы
ожидание.

### Потребители

`selkies`, `code-server`, `rustdesk`.
