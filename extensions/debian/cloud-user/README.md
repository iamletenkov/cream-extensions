# cloud-user

Библиотека (`kind: library`): скрипт `get_cloud_user.sh` печатает имя
пользователя cloud-init — того, под кем расширения настраивают сеанс,
автологин, ключи, автозапуск. Хуков нет; ставится как зависимость.

> **1.0.0 — новое в cream/v1** (каталог 5.0.0). Заменяет общий файл
> `lib/get_cloud_user.sh` раскладки 2 <!-- check-names: allow -->, который
> копировался в каждое расширение-потребитель.
> Логика та же; пути (`/home/<имя>`, `user-data.txt`) берутся под
> `CREAM_ROOT`, `yq` ищется по `PATH` вызывающего и запускается в чистом
> окружении.

## Как пользоваться

Манифест потребителя:

```yaml
depends: [{name: cloud-user, version: ">=1.0.0 <2"}]
```

Хук потребителя:

```bash
user="$("${CREAM_ROOT:-}/opt/cream/ext/cloud-user/get_cloud_user.sh")" || exit 1
```

Путь печатает `cream path cloud-user`. Удалить библиотеку, пока у неё есть
зависимые, cream не даст.

## Что возвращает

stdout — только имя; диагностика — в stderr.

| Ситуация | Код | Имя |
|---|---|---|
| есть `cloud-init` и `yq`, в userdata `user:` или `users[0].name` | 0 | из userdata |
| `cloud-init query userdata` не ответил, есть `/var/lib/cloud/instance/user-data.txt` | 0 | из файла |
| `cloud-init` есть, userdata ещё нет или `null` | 1 | — (гонка: вызывающий ждёт и повторяет) |
| userdata есть, пользователя в ней нет | 1 | — (ошибка seed, запасной путь не маскирует её) |
| нет `cloud-init` или `yq` | 0 | первая учётка с uid 1000…65533 и каталогом `/home/<имя>`; в stderr — `falling back to '<имя>'` |
| нет и такой учётки | 1 | — |

`yq` — расширение [`yq`](../yq/README.md) (mikefarah/yq). Без него на образе
с cloud-init библиотека уходит в запасной путь, который может выбрать
вендорскую учётку раньше cloud-init-овской, поэтому `yq` ставится вместе с
ней.
